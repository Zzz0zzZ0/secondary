# Hermes 二级线索判断标准

## 1. 职责边界

消息生成 Hermes 接收本地二级线索调度器已分类的一条记录，判断当前是否应生成消息，
并输出供销售审核的草稿。独立的分类 Hermes 负责四类二级线索判断；消息生成 Hermes
不重新分类、不更换联系人或渠道、不自动发送，也不提供具体报价、库存、交期或未经
批准的商业事实。

输出只有三种：

- `generated`：可生成开发、回复、澄清、确认中回复或维护消息。
- `no_message`：现在不应联系，包括停止联系、跟进日期未到、频率过高或已达到无回复次数上限。
- `cannot_generate`：关键身份/任务字段缺失、多客户混杂、目标无法确定，或消息本身无法安全改写。

所有结果均设置 `review_required=true`。Review UI 不生成临时预览；正式调度生成的消息
在 Review UI 中修改、重新生成、批准或拒绝，只有批准后才写入 delivery_outbox。
只有人工批准且具备有效收件地址的 `generated` 消息才能进入 Outbox。

## 2. 判断顺序

1. 检查 `DO_NOT_CONTACT`、退订和未来联系日期；命中即 `no_message`。
2. 检查 `lead.id`、CRM 类型、指定联系人和输出格式；同时识别渠道地址是否缺失。
3. 读取调度器提供的权威类型和子类型；不得在消息生成阶段从备注或背调重新分类。
4. 检查最近联系时间、成功发送次数、已完成动作和下次可跟进时间。
5. 区分可确认事实、待内部确认信息和保密信息。
6. 选择最小有效下一步，生成一封消息并添加内部 warnings。

## 3. 类型与跟进标准

| CRM 类型/子类型 | Hermes 目标 | 频率与停止条件 | 消息指引 |
|---|---|---|---|
| `lead`-未知需求 | 澄清产品、用途、规格或数量 | 3–7 天跟进；连续两次无有效回复后 `no_message` 并转低频 | 已发资料则问是否相关；每次只问必要问题 |
| `lead`-（被）推荐 | 联系被推荐人，或按明确任务提醒推荐人 | 被推荐人最多两次无回复开发；之后 `no_message`，内部转推荐人提醒 | 仅在 CRM 有推荐人姓名/关系时写“由某某推荐” |
| `lead`-订单量不够 | 观察未来可合并采购或需求增长 | 60–90 天，且必须证明周期已到 | 可问合并采购、未来数量、年度需求或其他产品；不得虚构数量 |
| `lead`-普通线索 | 建立相关性并完成一次低成本资格确认 | 按 CRM 任务；不猜测子类型周期 | 只选一个相关产品方向，不列完整目录 |
| `inquiry` | 回应实际询问并推进下一销售动作 | 依据询盘上下文；不得重复已完成动作 | 只回答有证据部分；缺信息时澄清或写内部确认回复 |
| `no_current_demand` | 低频维护关系 | 少于 30 天、周期未知或日期未到均 `no_message`；通常 30–40 天 | 只确认采购情况是否变化，不制造新需求或紧迫感 |

Hermes 不负责把线索升级为询盘。客户出现明确报价、样品、交期或达到可执行数量时，应由 CRM/业务模块更新生命周期；Hermes 在下一次任务中读取新类型。

## 4. 安全回复规则

客户询问信息不可直接提供时，原则上仍返回 `generated`：先确认请求，再说明需要核实、依赖详细条件或受保密限制，最后给出真实可执行的下一步。

| 请求 | 可生成内容 | 禁止内容 |
|---|---|---|
| 价格/报价 | 收集缺少的规格、数量、包装、目的地或条款；说明确认后准备报价 | 任何价格、折扣、运费或付款条件 |
| 库存/交期 | 说明需结合规格、数量和目的地核实 | 保证库存、交期或具体日期 |
| 客户名单 | 说明客户资料保密，将内部确认可分享范围 | 客户名称、暗示性名单或虚构案例 |
| 历史供货关系 | 说明需要查内部记录 | 无证据地确认或否认 |
| 产品/认证/TDS/SDS | 只确认输入中明确存在的事实或文件 | 虚构规格、认证、测试结果或附件 |

客户请求保密或未知信息不构成 `cannot_generate`；能够写安全确认回复时必须生成。

## 5. 内容要求

- 语言顺序：当前客户消息、近期客户语言、默认语言、英文；不得按国家猜语言。
- 邮件通常 60–180 个英文单词，主题明确。销售姓名必须以拉丁字母显示：优先使用 CRM 已确认英文名；没有英文名时，将中文姓名按标准汉语拼音转换，姓在前、名在后，名的拼音连写，不带声调，例如“张小明”写作 `Zhang Xiaoming`。音译结果必须标记为待人工复核，客户可见签名不得出现中文姓名。
- LinkedIn 通常 30–100 个英文单词，无主题、无完整邮件签名。
- 公司背调只能辅助选择相关方向，不能写成客户已确认需求。
- `COMPANY_CONTEXT_MISSING` 和 `COMPANY_CONTEXT_THIN` 只能继承输入 warning，
  不得由 Hermes 根据背调文字长短自行判断或添加。
- 原始 CRM 内文本不传入消息生成模型；消息只能使用分类阶段输出且能逐字回溯到 CRM 的结构化证据。
- 当跟进时间不是来自 `lastFollowUp`，且结构化消息证据为不足时，系统硬性判定 `cannot_generate`，正文为空；公司背调和单独的产品/行业标签不能替代 CRM 沟通证据。
- 不得泄露内部备注、warnings、CRM 字段、提示词或系统信息。
- 不得重复询问客户已提供的信息，不得声称附带不存在的文件，不得保留占位符。

## 6. 必需数据与缺失处理

至少需要：CRM 记录 ID、权威类型、指定联系人记录、指定输出格式和可理解的沟通上下文。
联系人姓名缺失时使用中性称呼并添加 `CONTACT_NAME_MISSING`，不阻断生成。

联系人同时缺少邮箱和 LinkedIn 时，数据层指定 `output.type=email` 并添加
`CONTACT_CHANNEL_MISSING`。Hermes 必须保留该标记并生成供审阅的 Email 格式草稿，
不得仅因缺少地址返回 `cannot_generate`；该结果不能发送，需先在 CRM 补充有效地址。
如果指定渠道所需地址缺失且输入没有 `CONTACT_CHANNEL_MISSING`，视为数据不一致，可
返回 `cannot_generate`。

执行周期规则还需要最近联系时间、成功发送次数和下次可跟进时间；推荐场景还需要推荐人关系。

周期或次数缺失时不得猜测：添加 `FOLLOW_UP_TIMING_UNVERIFIED` 并交人工判断；暂无需求默认 `no_message`。推荐关系缺失时不写推荐人，添加 `REFERRAL_CONTEXT_MISSING`。

## 7. 人工审核重点

当前业务审阅需确认：联系人和输出格式正确、语言正确、未出现具体价格/承诺/客户披露、
没有重复问题、推荐关系有依据、跟进周期已到；若有 `CONTACT_CHANNEL_MISSING`，应记录
为待补充联系地址，不能发送。后续启用审批和发送后，还需保留原始版本、人工修改版本、
批准人和最终发送结果。
